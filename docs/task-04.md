# Задача №4 Qildo. Реализация и проверка

## Контракт

`python beats.py song.wav out.json` читает полный микс и атомарно записывает массив объектов с полями `time` и `beat`. Времена отсчитываются от начала файла и строго возрастают. `beat: 1` — первая доля такта. При затакте сетка может начинаться с `beat: 3`. Для свободного вступления используйте первую долю, начиная с которой музыканты могут отсчитывать пульс. Спорные места следует обсуждать с разметчиком и отмечать в манифесте.

Декодер по умолчанию допускает 4 и 3 доли на такт и смену размера на границе такта. Если размер известен, задайте его через `--meters`. Для составных размеров, например 6/8, единица пульса зависит от разметки. Резкие смены темпа за пределами гипотез пульса и участки без устойчивого метра остаются сложными.

## Пайплайн

1. **Признаки.** WAV передискретизируется в 22 кГц. Временная сетка имеет шаг 10 мс. Признаки строятся по мощности каналов, поэтому противофазный сигнал не пропадает. Алгоритмический режим использует многополосную силу атак, низкие частоты и изменение хроматического профиля.
2. **Пульс.** Автокорреляция предлагает несколько периодов, включая уровни ×2 и ÷2. Для каждого кандидата динамическое программирование расставляет доли по всей записи. Ранжируемый режим дополнительно строит траектории темпа по восьмисекундным окнам с шагом в секунду. Переходы между периодами штрафуются, а устойчивый новый темп может компенсировать этот штраф. Поиск ограничен примерно 45–220 BPM. [Метод Эллиса](https://labrosa.ee.columbia.edu/projects/beattrack/)
3. **Совместная оценка такта и сетки.** Для каждой гипотезы пульса декодер оценивает несколько положений доли в окне ±70 мс и меняет размер только после последней доли такта. Смена размера штрафуется. Среди гипотез выбирается сетка с лучшим сочетанием поддержки долей и акцентов. Слабый приоритет первой доли у начала файла помогает разрешить неоднозначность, сохраняя возможность затакта. [Модель совместного декодирования долей и начала такта](https://www.cp.jku.at/research/papers/Boeck_etal_ISMIR_2016.pdf)
4. **Модель.** Многоуровневая residual CNN получает 64 log-mel полосы и их временные разности. Дилатации дают около 5,1 секунды контекста с каждой стороны. В варианте `hierarchical` модель оценивает вероятность доли и условную вероятность начала такта внутри доли. Временная аугментация сдвигает признаки и обе цели одновременно. Окна инференса соединяются перед декодированием.
5. **Выбор источника.** В режиме `hybrid` при высокой акустической поддержке и стабильных интервалах выбирается акустическая сетка. При доступных весах для остальных записей используется совместное декодирование активаций CNN. В акустическом режиме для длинных стабильных записей есть дополнительная проверка спектральных гипотез темпа. Кандидат должен согласоваться с атаками в разнесённых частях трека и с тактовыми акцентами. Порог по плотности сетки ограничивает замену случаями, где исходный трекер, вероятно, пропустил метрический уровень.
6. **Ранжирование.** Обучаемая линейная модель сравнивает сетки, учитывая покрытие атак, поддержку альтернативного пульса между долями, согласованность акцентов, стабильность интервалов и края записи. При калибровке группы и датасеты получают веса независимо от числа гипотез, а функция цели штрафует серии ошибок темпа ×2 и ÷2. Ранжировщик привязан к конкретному чекпойнту по SHA-256.
7. **Выход.** Первая доля такта всегда присутствует в общей сетке. При выводе в JSON проверяются порядок времён, границы записи и положительные номера долей.

## Манифест и разметка

```json
[
  {
    "id": "original-song-01",
    "group": "original-composition-01",
    "split": "test",
    "audio": "audio/original-song-01.wav",
    "reference": "reference/original-song-01.json",
    "source": "Original recording, author and date",
    "license": "Original recording and annotation with commercial-use permission",
    "tags": ["full-song", "solo-intro", "4/4"]
  }
]
```

Пути относятся к манифесту. Эталон имеет тот же формат, что и выход CLI. Допустимые части — `train`, `validation`, `test`. Дубли, ремиксы одной песни и связанные записи используют одну группу. Укажите коммерческие права и на аудио, и на разметку. Для сторонних файлов сохраните ссылку на оригинал, версию, автора и лицензию.

- **GuitarSet v1.1.0** импортируется из архивов микрофонных WAV и JAMS. Группа объединяет исполнения одной музыкальной основы. Доли взяты из слоя `beat_position`. Это короткие гитарные записи с исходной сеткой датасета. Известные замечания к разметке приведены в публикации релиза. [GuitarSet, CC BY 4.0](https://zenodo.org/records/3371780)
- **Groove MIDI Dataset** подходит как вспомогательный источник ударных. Импортер строит сетку по метаданным MIDI, ограничивает края записи и делит треки по барабанщику. Служебные паттерны, сыгранные несколькими барабанщиками, допускаются только в тесте. [Groove MIDI Dataset, CC BY 4.0](https://magenta.withgoogle.com/datasets/groove)
- **Полные песни** добавляйте с проверенной лицензией записи и собственной разметкой. Для локальной продуктовой проверки нужны независимые композиции с затактом, тихим вступлением, входом барабанов, паузой, синкопами и сменой темпа. Для спорных вступлений нужен второй разметчик. [Лицензирование аудио FMA](https://github.com/mdeff/fma#acknowledgments-and-licenses)

Размечайте от первой музыкальной доли. Затем прослушайте эталон с кликами, включая начало и конец каждого перехода. Для треков без размеченных долей храните пустой массив. Ложные клики на них учитываются отдельно от средней F-меры.

## Как читать отчёт

- **Beat F1** и **Downbeat F1** используют окно ±70 мс от нулевой секунды. `CMLt` считает правильный уровень пульса, `AMLt` допускает альтернативный. Также выводятся `CMLc` и `AMLc` для непрерывных участков. Вызовы метрик сделаны напрямую, чтобы сохранить первые пять секунд. [Документация mir_eval](https://mir-eval.readthedocs.io/latest/api/beat.html)
- **Начало.** Проверяется совпадение первого предсказания с первым эталоном. Отдельно считаются ложные ранние клики и совпадения среди первых восьми эталонных долей.
- **Темп.** В полном эталонном такте с локально стабильными интервалами сравниваются медианные интервалы. Серии минимум из двух тактов с отношением темпов около 2 или 0,5 учитываются в `tempo_error_bars`. Допуски отношения — 0,25 и 0,15 соответственно. Пропуски целых участков по-прежнему видны в F1 и CMLt.
- **Фаза.** Сдвиг на соседнюю позицию учитывается в серии из двух и более тактов. Для этой проверки требуются совпадения всех долей и правильное их число внутри такта. При сравнении версий `common_phase_bars` показывает ошибки на общих подходящих тактах.
- **Сравнение.** Сводка содержит средние по трекам и результаты по тегам. При `--compare` отчёт даёт попарные разницы и бутстрэп по группам композиции. При трёх группах оценка интервалов остаётся предварительной.

## Слепая проверка

```bash
python render_clicks.py song.wav baseline.json candidate.json runs/listen-01 --seed 7348
```

Слушателю передайте `A.wav` и `B.wav`. Ключ `answer-key.json` остаётся у организатора. Для каждой пары используйте отдельное зерно. Запишите выбор и причину по трём вопросам: где проще войти с начала, сыграть переход и зациклить такт. Для длинного трека можно задать `--start` и `--end`. После сбора ответов подсчитайте победы, поражения и ничьи.

## Условия готовности

- Инференс, обучение, импорт, оценка и подготовка A/B доступны отдельными командами. Для базового и ML-режимов предусмотрены офлайн-образы.
- Кандидат для продуктовой проверки должен стабильно превосходить локальный baseline на независимых полных песнях, включая первую долю и фазу такта. Зафиксируйте выбор модели и пороги до оценки.
- Готовность к использованию подтверждается тестом Qildo на закрытом наборе, слепым прослушиванием и замером времени на выбранном оборудовании.
